# Frontend audit

## Narrative Findings (AI reviewer)

### UI-01 — BLOCKER / P1: Switching screens bypasses the unsaved-notes exit guard

**Files:** `assets/index.html:119`, `assets/index.html:301`, `assets/notes-ui.js:382`; native chain `src/ca/kylekeith/shottime/MainActivity.java:330-336,355-371`.

The hamburger screen navigation hides QC Notes without checking its pending save state. `ShotNotesUI.back()` returns false whenever QC Notes is hidden, and the calculator root then returns false from `closeTopSheet()`. Native `handleBack()` treats that as permission to exit. The failed `flush()` in native `onPause()` has a null callback and does not prevent destruction of the WebView, so the staged, unsaved note changes are lost.

**Confirmed browser reproduction:** Seed a valid job/list containing one weld. Make `Storage.prototype.setItem` throw only for `shottime.notes`. Use Add manually > Add welds to add a different CN. The page reports `Not saved — keep the app open. Retry saving or export your data.` and shows two rows, while saved storage has one. Back while still in QC Notes correctly returns true. Open the actual hamburger menu and click Shot Time Calc; the same `closeTopSheet()` returns false while `ShotNotesUI.flush()` returns false. Native source tracing confirms the default Back/destruction consequence. No handset execution was performed.

**Fix:** Put a global notes save/recording guard before changing screens and before allowing native exit, independent of the currently visible section. On failure bring QC Notes/recovery back into view and consume Back. Add a browser regression that follows the hamburger route after quota failure, plus native coverage that a false flush cannot be ignored at an explicitly requested exit.

### UI-02 — BLOCKER / P2: Closing CN search leaves hidden selections in later daily-list bulk actions

**Files:** `assets/notes-ui.js:164`, `assets/notes-ui.js:287-294`, `assets/notes-ui.js:261-262`, `assets/notes-ui.js:301-306`.

Search and daily-list selection share the same global `cnSelection` map. Closing the search dialog does not clear it. Starting a later press-and-hold selection adds the visible card to the retained map. CNs selected on other lists remain selected but have no checkboxes/cards on the daily-list screen. The bulk confirmation gives only counts and number ranges, so it does not reveal which hidden CN or date will also be modified.

**Confirmed browser reproduction:** Create two lists in one job: list one has CN-1 and list two CN-2. Open list one, Search CN#, check CN-2, and Close. Start selection on CN-1 using the long-press handler's keyboard equivalent, Shift+Space. The daily list has one visible checked checkbox but the toolbar reports two selected. Delete selected > Preview > Confirm deletion removes both lists' rows. Browser output: `visible checked 1`; saved lists afterward: `[["one",0],["two",0]]`.

**Fix:** Scope selections to the search session or explicitly clear search selections when closing/cancelling search. Starting a new daily-list selection should begin with that list's selection only. If cross-list selection is intentionally retained, render all retained selections with CN and date and provide deselection before allowing a destructive action; list those identities in the confirmation. Add search-close-to-long-press regression coverage.

### UI-03 — BLOCKER / P2: Saved standalone drafts block bulk changes with no visible resolution control

**Files:** `assets/notes-ui.js:363-375`, `assets/notes-ui.js:225-231`; cross-module gate `assets/notes-jobs.js:89`.

The entry-screen cleanup removed the standalone instruction form but retains preexisting `list.draft` values. The form is now rendered only for a pending review. A migrated/saved list with a nonblank draft and no pending items therefore has no control to inspect, finish, or discard that draft. The new bulk operation rejects any affected job containing such a draft, including a different list in the same job, with an instruction the user cannot carry out through the available draft controls.

**Confirmed browser reproduction:** Seed a valid current-schema list with one weld, `draft: "CN-2 has one"`, and `pending: []`, representing a draft retained from the earlier instruction UI. Load the app and open the list. There are zero textareas. Start selection and choose Delete selected > Preview changes: it errors `Resolve pending instructions and drafts in the affected jobs first.` Closing the dialog or reopening/reloading the list exposes no saved-draft resolution control.

**Fix:** Surface nonempty standalone drafts as recoverable pending work with explicit review/discard actions, preserving their contents. Alternatively provide a saved-draft section in Settings and navigate to the precise blocking list from the bulk error. Do not silently erase retained drafts. Add a migration/upgrade-style browser test with a draft and no pending item.

## Cross-review validation: DATA-03 unrecovered transcript can be acknowledged

This evidence belongs to the data review's DATA-03 finding and is not counted as a separate UI finding. Relevant UI lines: `assets/notes-ui.js:55,58-64,138,158`.

Browser reproduction supplied a stopped, nondeferred session with ID `oversize`, list ID `one`, and 500 events each containing `this unrecognized statement describes a spool and needs review`. The UI displayed `Voice transcript needs recovery: Invalid pending instruction.` Saved notes contained `pending: []` and no `voiceTranscripts`. The recovery panel was hidden, so Retry saving was not available through normal interaction.

Pressing Back to daily lists and reopening the original list calls `navigate()`/`persist()`. `persist()` sets `voiceSaved` true because a matching list exists, without proving the oversized transcript was saved. The microphone becomes enabled. Clicking Start recording emitted this captured browser request:

`shottime://voice/start?list=one&previous=oversize&input=phone`

At that point saved notes still had no pending item or transcript archive. Thus a routine navigation acknowledges the unrecovered session and permits a new native recording to replace its journal. Treat DATA-03 as P1 data-loss risk. The fix must track durable session/segment acknowledgement, not merely matching list existence, and expose recovery for rejected transcripts while preventing replacement until recovery succeeds.
